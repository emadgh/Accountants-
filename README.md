# Accountants Web — حسابداری تک‌صفحه‌ای

برنامه حسابداری فارسی و RTL برای مدیریت طرف‌حساب‌ها، کالا و خدمات، فاکتور، انبار، دریافت و پرداخت، چک و گزارش‌ها.

## اجرا در توسعه

نیازمندی: Node.js نسخه 22.13 یا 24 و npm.

```bash
npm install
npm run dev
```

سپس برنامه را از `http://localhost:3000` یا `http://127.0.0.1:3000` باز کنید. برای ورود از دستگاه دیگر باید برنامه روی سرور روشن باشد و HTTPS را از طریق reverse proxy تنظیم کنید؛ جزئیات در [راهنمای استقرار](./DEPLOYMENT.md) آمده است. هنگام خاموش‌بودن سرور، ساخت و ذخیره سند ممکن نیست.

## پایگاه داده

داده‌های برنامه در فایل SQLite در مسیر `data/accountants.sqlite3` و فایل‌های پروژه در پوشه `data/attachments` ذخیره می‌شوند. مسیر پیش‌فرض کنار کد است؛ برای استقرار، `ACCOUNTING_DATA_DIR` را به دیسک پایدار و بیرون از پوشه `public` تنظیم کنید. فایل‌ها هنگام اولین درخواست دیتابیس ساخته می‌شوند. سرور از SQLite داخلی Node.js (`node:sqlite`) استفاده می‌کند و `DATABASE_URL` لازم نیست.

رمز عبور به‌صورت hash ذخیره می‌شود و نشست ورود در کوکی `HttpOnly`، `SameSite` و امن در محیط HTTPS نگهداری می‌شود؛ جاوااسکریپت صفحه به توکن نشست دسترسی ندارد. نوشتن عادی از فرمان‌های معتبر با کنترل بازنگری و جلوگیری از تکرار درخواست انجام می‌شود. برای پشتیبان‌گیری و بازیابی اطلاعات، از بخش «تنظیمات → پشتیبان‌گیری» استفاده کنید؛ Snapshotهای جدید داده و پیوست‌ها را با هم نگه می‌دارند.

## دستورات

```bash
npm run dev        # اجرای توسعه
npm run typecheck  # بررسی TypeScript
npm test           # آزمون‌های جریان حسابداری و API
npm run build      # ساخت نسخه تولید
npm start          # اجرای نسخه تولید؛ پس از build
```

جزئیات مسیر توسعه در [ROADMAP.md](./ROADMAP.md) نگهداری می‌شود.


## ساختار توسعه و تجربهٔ مشترک

- پلن و شواهد اجرای بازآرایی: [STRUCTURE-UX-PLAN.md](./STRUCTURE-UX-PLAN.md).
- `lib/domain/`: عملیات مستقل از React برای اسناد، پرداخت و چک، موجودی، حسابداری و کسب‌وکار؛ اعتبارسنجی، نرمال‌سازی داده قدیمی، محاسبات پروژه و گزارش در فایل‌های جدا هستند.
- `lib/store.ts`: وضعیت و اتصال فرمان‌ها به ذخیره‌سازی؛ پیش‌نمایش محلی جای تأیید سرور را نمی‌گیرد. کامپوننت‌ها از selector محدود استفاده می‌کنند؛ نمایه‌های آرایه‌های تغییرناپذیر در `lib/domain/indexes.ts` بازاستفاده می‌شوند.
- فرمان `domain.execute` شامل نام عملیات، ورودی و seed شناسه است. سرور عملیات را روی آخرین داده اجرا و سند و گردش را تولید می‌کند. `commandId` و `expectedRevision` از ثبت دوباره و تعارض دو تب جلوگیری می‌کنند؛ خروجی مالی مستقیم کلاینت روی دیتابیس موجود پذیرفته نمی‌شود. bootstrap اولیه و import مدیر مسیرهای کنترل‌شدهٔ جدا دارند.
- `persistOperation` و hookهای `usePersistedAction` / `useAsyncSubmission` پاسخ، خطا و قفل ارسال را مشترک می‌کنند. فرم پس از شکست ذخیره باز می‌ماند؛ «بارگذاری دادهٔ تازه و تلاش دوباره» اتصال را بازیابی می‌کند. نمایش موفقیت و چاپ قطعی پس از تأیید سرور انجام می‌شوند.
- اعتبارسنجی عادی روی رکورد تغییرکرده و وابستگی‌های آن است؛ import و restore کل داده را بررسی می‌کنند. ویرایش پروفایل به صحت فاکتور تاریخی نامرتبط وابسته نیست.
- `components/management/`: صفحات مستقل؛ `management-views.tsx` فقط مسیر سازگاری importهای قبلی است.
- `components/forms/`: پرداخت، تراکنش مالی، انتخاب/ساخت طرف حساب و ورودی عدد ردیف سند. جدول چاپی و چیدمان هر قالب فاکتور مستقل از جدول مدیریتی باقی می‌مانند.
- `RecordTable` و `FilterBar`: جدول نوع‌دار، مرتب‌سازی، صفحه‌بندی، حالت خالی و فیلتر مشترک. `Field` ارتباط label، خطا و توضیح با ورودی را برقرار می‌کند؛ `AttachmentList` و `SettlementSummary` برای نمایش مشترک‌اند.
- `/documents?kind=sale` و `/documents?kind=purchase`: فهرست مشترک؛ `q`، `status`، `from`، `to`، `customerId`، `projectId` و `balance` در URL حفظ می‌شوند. `/sales` و `/purchases` با همان queryها به آن هدایت می‌شوند.
- تنظیمات «چیدمان منو» سه حالت خدمات و طراحی، فردی و فروشگاهی دارد؛ فقط میان‌برها را مرتب می‌کند. «کاهش افکت‌ها» و ترجیح کاهش حرکت سیستم رعایت می‌شوند.
- مسیرها، گروه‌های سایدبار و قابلیت‌های صفحه درباره در `lib/app-features.ts` متمرکز هستند.

یک نصب همچنان یک دفتر مالی دارد. پروفایل‌های صادرکننده دفترهای مستقل شرکت و شخص نیستند؛ بازآرایی تعریف مالیات/درآمد یا اسناد تاریخی را بازنویسی نمی‌کند.

برای آزمون هم‌زمان با سرور توسعه، `NEXT_DIST_DIR` را به یک مسیر خروجی جدا مانند `build/verification` و `ACCOUNTING_DATA_DIR` را به پوشه داده آزمایشی جدا تنظیم کنید؛ روی داده واقعی seed یا آزمون مالی اجرا نکنید.

CI برای Node 22 و 24، typecheck، تست‌ها و build را اجرا می‌کند. آخرین نتیجه و محدودهٔ مرور دستی در فایل پلن ثبت می‌شود.

تغییر نوع کالا به خدمت (یا برعکس) برای ثبت‌های جدید اعمال می‌شود. سرور نوع فاکتورهای قطعی قبلی را در `Product.invoiceKinds` نگه می‌دارد تا تسویه‌ها، اسناد حسابداری، کاردکس، مرجوعی و هزینهٔ تاریخی پروژه تغییر نکنند. موجودی تاریخی با تغییر نوع صفر نمی‌شود و بازسازی اسناد قدیمی انجام نمی‌شود؛ بکاپ این فراداده را هم حفظ می‌کند.
